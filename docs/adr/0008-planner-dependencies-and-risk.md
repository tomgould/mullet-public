# 0008. The planner states dependencies, one-way doors and open questions

Status: Accepted

Context: Mullet's own ledger held 40 failed attempts. 6 failed G3 ("19 risky edits in a mechanical node": the planner called a step mechanical and the worker's change was risky), 4 failed G2 (files outside the step's scope, such as a new test file the plan did not list) and 5 failed G1 (no change). The plan schema had no way to say one step waits for another, the prompt only asked for siblings "in the order they should be done", and risk came only from a keyword match (`is_risky` in `mullet/jobs/ladder.py`). Another orchestrator's planner builds a "blocked by" graph with three tests, flags one-way doors and lists open questions; Mullet's had none of this.

Decision: `NodeSpec` (`mullet/jobs/types.py`) gains `after: list[str]` (nodes finished first) and `door: "two-way" | "one-way"` (default two-way); the plan gains `open_questions` (at most 10, 400 characters each). `validate_plan` (`mullet/jobs/planner.py`) refuses an `after` that names no node or itself, a cycle, or a node the runner would not have finished yet (it runs nodes in list order, children before their parent). The prompt gives the three dependency tests (B needs code A adds; they touch the same files or modules; B depends on a decision or API shape A settles), the one-way test (a public API, a default users build on, a removal, a persisted format), says to list new test files in scope, says a step that deletes, kills, sends data or changes a public API or persisted format is never mechanical, and allows open questions only for what could not be verified in the code. A one-way step is risky, so it is Claude-first, and it gets G7 in every job, ladder or not, even when the job was planned with `--no-review`: the review exists because the step is hard to undo, and turning review off is a choice about cost on ordinary steps, not about these. That review must pass with a verdict of its own (`JobRunner._risk_reviewer`): a block fails the attempt, and a review with no verdict, or an approval given only when the reviewer was asked again for its verdict, pauses the job for a person. The risky words still apply in ladder jobs, so a plan can raise risk but never lower it. `mullet job plan` and `mullet job show` list one-way steps and open questions under the tree. A reply with no usable plan is asked for again in the same Claude session, with the reason, up to `jobs.reask_attempts` times (default 1, 0 off); the Claude executor's `ask` keeps and resumes that session (`persist`, `resume`).

Consequences: The approver sees which steps are hard to undo and what the planner did not know before anything runs. Plans stored before this change load unchanged, since both fields have defaults. The runner still executes in list order; `after` is checked against that order rather than scheduled, so it documents and enforces order but does not reorder or run steps in parallel. Whether the prompt changes reduce the G1, G2 and G3 failures needs new ledger figures to confirm. A kept planner session leaves a Claude session file behind while re-asks are on.
